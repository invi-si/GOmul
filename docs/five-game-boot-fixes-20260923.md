# 요청한 다섯 게임의 부팅 재검증 — 2026-09-23

Mac Android AVD에서 요청한 다섯 게임만 1배속으로 검사했다. 매 검사에는 별도의 캐시 저장 공간을 사용했다. 부팅 및 아래 경로 확인이며 전체 게임 완료를 보증하지 않는다.

| 게임 | 재현 결과 | 수정 및 재검증 |
|---|---|---|
| 놈투 | 빈 4,100바이트 버퍼를 SMAF로 해석하면서 시작 직후 예외 | 버퍼 생성과 재생 시 디코딩을 분리. 게임 화면에 진입하고 프레임 갱신 확인 |
| 메이플스토리 궁수편 | setBuffer에 전달된 1,024바이트 빈 버퍼를 즉시 해석하면서 예외 | 전달된 버퍼를 유지하고 재생 시 읽도록 수정. 시작 오류 없이 도입 장면 진입 |
| 라그나로크 바이올렛 | 안내에 따라 재시작한 뒤 UI 컨텍스트 태그를 주소로 읽어 메모리 오류 | LGT UI 생성에서 컨텍스트 핸들 직접 전달과 핸들 슬롯 포인터 전달을 모두 처리. 재시작 후 새 게임 슬롯 화면 진입 |
| 이노티아연대기2 | 첫 인증 오류 후 단순 확인 입력만 반복하면 종료 | 수정 불필요. 첫 종료 후 재실행하고 인증 안내가 나타난 다음 왼쪽으로 ‘예’를 선택하고 확인하면 제목 화면 진입. 기본 ‘아니오’를 누르는 자동 검사는 실패 판정 근거가 아님 |
| 게임빌2010프로야구 | 현재 설치된 LGT 패키지는 1배속에서도 프레임 0인 검은 화면 | 미해결. paintClet 경로의 LGT 0x6a/0xee 서비스가 미구현. 호출 규약/이벤트 전달 계약이 확정되지 않아 임의 성공값이나 게임 전용 우회는 추가하지 않음 |

## 구현 근거와 검증

[WIPI Clip SDK 문서](https://nikita36078.github.io/J2ME_Docs/docs/WIPI_API_1_1_1/org/kwis/msp/media/Clip.html)에 따라 버퍼 크기 생성자는 빈 저장 공간을 만들고, setBuffer는 호출자가 제공한 배열을 보관한다. putData는 남은 공간만큼 데이터를 복사한다. 이 변경은 초기화 단계에서 미디어 해석을 하지 않으며 실제 재생 시에는 기존 SMAF 검증을 유지한다. 전체 스트리밍/녹음 지원을 구현했다는 의미는 아니다.

회귀 검사는 빈 버퍼 생성, 분할 입력, 용량 제한, 데이터 지우기, 잘못된 범위, 버퍼 할당 후 호출자에 의한 내용 변경, 잘못된 미디어의 재생 실패, LGT UI 핸들의 두 전달 형태를 확인한다. wie-wipi-java 72개, wie-midp 61개, wie-lgt 40개 라이브러리 테스트 통과. cargo fmt, cargo clippy --workspace 및 Android 빌드 통과(기존 경고 존재).

비공개 five-games-20260923 작업 폴더에 원본 APK/앱 데이터 백업, 각 게임의 원본 패키지, 전후 로그/화면, Rescue와 격리 저장 데이터가 있다. Rescue는 기록 재생 자료이며 임의 시점의 완전한 RAM 덤프가 아니다. 게임 자료는 저장소에 포함하지 않는다. 이전 전체 3배속 검사 결과를 전체 호환성 판정으로 사용하지 않는다.
