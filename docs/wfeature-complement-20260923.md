# W-Feature 후속 비교와 GOmul 독립 구현

비교 기준: [movingwoo/wfeature](https://github.com/movingwoo/wfeature) `bb2294fcfa3212856f896209d05b934575f30265` (2026-09-21). 이전 비교 기준 `a621a6a56dbc6e8f5da967d23218ec750d73001c` 이후의 변경을 먼저 살폈다. 해당 프로젝트는 자체 소스를 MIT로 배포하며 별도 서체·필터 등의 제3자 고지를 제공한다. 이번 변경은 참고 프로젝트의 코드를 옮기지 않고, 공개 API 문서와 GOmul의 구조·테스트를 근거로 독립 구현했다.

| 영역 | GOmul 결과 |
| --- | --- |
| SKT 별도 JAR 자료 | `XFile(String, String)`이 패키지의 가상 파일시스템에 있는 별도 JAR 엔트리를 읽는다. 파일·엔트리 경로, 없는 자료, 손상된 아카이브, EOF와 닫기를 검사한다. 테스트 자료는 직접 만든 4바이트 파일 한 개가 들어 있는 JAR이다. |
| LGT 네이티브 Java | 기존 `Vector.setElementAt` 구현이 LGT 네이티브 슬롯 26에 등록되지 않았음을 회귀 테스트로 재현한 뒤 ABI 자료에 매핑했다. 네이티브 호출에서 처음·가운데·마지막 요소 교체, 크기 유지와 잘못된 인덱스 예외를 확인했다. 메서드의 계약은 [CLDC 1.1 Vector 문서](https://docs.oracle.com/javame/config/cldc/ref-impl/cldc1.1/jsr139/java/util/Vector.html)를 따른다. |
| WIPI 그림 읽기 | `Graphics.getRGBPixels`가 현재 그림과 좌표 이동을 반영하여 RGB 배열을 채운다. 행 간격·배열 경계·영역 밖 픽셀을 검사한다. [KTF WIPI Graphics 문서](https://nikita36078.github.io/J2ME_Docs/docs/KTF_WIPI_API/org/kwis/msp/lcdui/Graphics.html)의 int 배열 계약에 한정했다. byte 배열 `getPixels`의 장치별 색 형식은 추측하지 않았다. |
| 일반 저장 신뢰성 | 레코드 교체 내용을 디스크에 동기화한 뒤 이름을 바꾸며, 새 레코드 쓰기 실패는 게스트가 처리할 수 있는 실패 ID로 돌려준다. 부분 쓰기 실패 시 원래 레코드를 보존한다. |
| Android 저장 이동 | 게임 항목 길게 누르기 메뉴에 일반 저장 ZIP 내보내기·가져오기를 더했다. 동일한 게임 ID, 경로, 길이, SHA-256을 검증하고 임시 위치에서 검사를 끝낸 뒤 교체한다. 기존 일반 저장은 앱 내부에 보관한다. 게임 아카이브와 빠른 저장 슬롯은 포함하지 않는다. 이 형식은 W-Feature의 `.wfs`와 호환되지 않는다. |
| 브라우저 오디오 | 중단된 AudioContext를 다음 사용자 조작에서 다시 활성화하고, 중복 재개를 하나로 합쳐 재생 시계를 다시 맞춘다. 재생 중인 노트를 다시 시작하지 않는다. |
| 브라우저 입력 | 기본값이 꺼진 5/확인 연사 전환을 더했다. 누르는 동안 연사 또는 켜고 끄는 연사를 선택할 수 있다. 일반 키 이벤트를 보내며 포커스 상실·게임 종료·모드 변경 시 누른 키를 해제한다. |

채택하지 않은 항목도 있다. 기존 GOmul이 이미 지원하는 RMS 수명주기, 동봉 저장, 일부 Java 컬렉션 메서드와 파일 열기 동작은 다시 만들지 않았다. SGS/GNEX는 확인된 대상 자료가 없고 참고 프로젝트에서도 부분 지원이다. 기종·게임별 인증 우회 및 화면 주기 조정은 GOmul의 재현 자료 없이 가져오지 않았다. 실행 중인데 오디오 시계만 멈춘 상황을 강제로 재시작하는 처리와 브라우저 OS 입력기는 실제 기기에서의 대상 선택·재현 증거가 더 필요하다. PWA 서비스 워커 정리는 현재 GOmul 브라우저 구조에 해당하지 않는다. CPU 실행 정책과 게임 타이머는 변경하지 않았다.

검증: `cargo test --workspace` 통과, `cargo clippy --workspace` 통과(기존 경고 있음), 브라우저 JavaScript 테스트 44개와 TypeScript 검사 통과, WASM 대상 검사 통과. Android 저장 이동의 Java 테스트 및 Java 컴파일 통과, Android 디버그 APK 빌드 통과. 실제 Android 기기에서 새 UI를 조작하거나 각 게임의 호환성·속도 향상을 측정한 결과는 아직 없다. 테스트에는 게임 아카이브나 사용자 저장 파일을 버전 관리에 추가하지 않았다.
